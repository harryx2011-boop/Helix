**Gaps between the plan and the build**, each verified in code:

1. **Sharing is a URL copy.** `shareRoleLink` in `components/app/actions.ts` copies `/roles/<slug>?persona=<slug>` to the clipboard. The PRD's team story (§9: "a shareable link that exports the config, opened with no login") does not exist. `persona_shares` allows a null `profile_id`, so it never needed accounts.
2. **The Settings API key does nothing.** `sidebar-settings.tsx` stores `settings.apiKey`; no code reads it. It was reserved for a wizard model step that was never built and is now dropped (§7.3).
3. **Phase 4 (accounts) is zero-started**, and is now dead (§7.6).
4. **Version history was removed in 1.2.0**, but every fork still records `sourceVersion`. Nothing surfaces it.
5. **Search is keyword plus three chip filters.** The `tsvector` column in the schema is unused because the catalog is markdown on disk, not rows.
6. **Persona already has a second user with no product surface.** `~/.claude/rules/persona-agents.md` greps `content/INDEX.md` to pick a system prompt for every role-shaped agent dispatch. The only programmatic route is `GET /api/catalog?role=&persona=`, an internal helper for the card menu.

## 3. The three tracks

Each ships on its own commit as its own MINOR, each verifiable without the next.

### Track 1 — Close the loop (Persona 1.3.0)

- **Share links that carry the config.** `POST /api/share` (Next route handler, service role, `server-only`) inserts a frozen copy of `bodyMd` + `values` into `persona_shares` with a null `profile_id` and returns a token; `/s/[token]` resolves server-side and opens the editor with a "Fork this" action. Tokens are never selectable from the browser, as the schema already enforces. This is the whole teams story now that accounts are dead.
- **Version chip on forks**: "forked from Support Agent v3, now v4" with a refresh action, since `sourceVersion` is already recorded.
- **Editor ceiling raised to code blocks and tables.** Two Tiptap extensions. Export has to follow: fenced blocks map cleanly to `.md`, tables need a pipe-table serializer for `.md`, a plain-text layout for `.txt`, and a rendered grid in the `.pdf` path. Export is where the cost is, not the toolbar.
- **Remove what is dead.** The Settings API key field and its `settings.apiKey` slot (nothing reads it, nothing will). The `shareRoleLink` clipboard path once real shares exist. `@clerk/nextjs` from `apps/persona/package.json` (zero imports, and no accounts ever). `PERSONA.md` §3's "anonymous first, account second" section is superseded by this file.
- **Rebalance rides here** if the track is green first: the 1.2.0 process (haiku fleet writes, sonnet refines to the Support Agent bar, one LLM guide each) pointed at Sales, Security, Legal and Education, then `pnpm check:content`.

Done when: a visitor fills Support (Chat), shares it, a second browser opens the link and forks it; a fork with a table exports to all four formats and each opens correctly; tsc + lint + `check:content` clean; the removed dependency is gone from the lockfile.

### Track 2 — Visual + IA revamp (Persona 1.4.0)

**Reference bar: the Helix landing**, for motion, spacing and polish only. Persona keeps its own palette. **Brand: sibling, sharpened.** Light, Inter, black primary, blue for actions, the role tints. What travels from Helix is the motion grammar: pill-shaped primaries with the fluctuating fill, hairline rows, in-view-gated ambient fields that go static under reduced motion. **The hero keeps the cycling role pill** ("System prompts for [Sales] teams"). **The current icon stays**; no logo work.

Scope inside the track:

- **Landing.** The breadth hook is the roles grid; today it sits below two mockups. Lead with it after the hero. Keep the role pill H1, the search demo, and one app mockup; cut the second and third mockups if they fail the reference comparison. Count-free copy stays.
- **App shell.** The three sidebar tabs mix navigation (Search), documents (Editor) and preferences (Settings). Search becomes the sidebar's whole job, forks become a "Library" section under it, Settings moves behind a footer control. One primary action per screen.
- **Role page.** Persona dropdown, platform tabs, and the wizard launcher compete for one row. "Fill in the blanks" is the hero action; the rest go to the burger.
- **Share landing `/s/[token]`** gets designed here, not in Track 1's placeholder chrome.
- **Reviews before commit**, in the project's fixed order: `interface-review` → `review-animations` → tastemaker anti-slop → `ui-anti-vibe` checklist. Screenshots at 1440 and 390 for `/`, `/roles`, `/roles/support-chat`, `/editor/<id>`, `/s/<token>`, compared side by side with the Helix landing shots.

Done when: every screenshot passes the four reviews and the Helix comparison; hero pill and current icon unchanged.

### Track 3 — Agent surface, standalone (Persona 1.5.0)

Persona is already infrastructure for this machine's agents. Make that a public surface without touching `apps/api`.

- `GET /api/personas`: the `INDEX.md` data as JSON (role, slug, name, tone, platforms, placeholder keys). `GET /api/personas/<role>/<slug>`: frontmatter + raw body, `text/markdown` when the `Accept` header asks for it. Cache-friendly, no auth.
- A generated `/skill.md` teaching an agent to list, pick and fill a persona. Same preamble shape as Helix's `lib/skill.ts`, generated from the catalog so it never lists a persona that does not exist.
- `~/.claude/rules/persona-agents.md` switches from grepping the file to fetching the route, with the file as fallback. That is a harness edit, not a Persona one.
- No MCP tool. If Helix ever wants one it proxies these routes from its side.

Done when: `curl` returns the Support (Chat) default body, and the skill file drives a role-shaped dispatch end to end.

### Semantic search, patch-sized, any time after a track is green

Embeddings computed at build time (all-MiniLM already loads in `apps/extract`'s venv; 112 × 384 floats is roughly 170 KB of JSON), a cosine loop in `sidebar-search.tsx`, keyword search kept as the fallback. No backend, no schema.

## 5. Out of scope

- Accounts, sign-in, cloud sync, Clerk on Persona. Dead, not deferred. The `persona_forks`, `persona_favorites` and `persona_template_values` tables stay in the schema unused; removing them is a migration for another day.
- A separate repo, a second Vercel project, or a backend of Persona's own.
- Anything in `apps/api`.
- "Try it" / running prompts against a provider, from the browser or through Helix.
- Company favicons or brand marks on platform tabs (platforms stay generic Lucide glyphs).
- Pricing, testimonials, counts in copy, suggestion-pill triads (global rules).
- A new logo. Changing the port (4200) or the content file format.
